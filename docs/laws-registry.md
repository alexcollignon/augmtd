# THE LAWS REGISTRY — the human view (rendered from `docs/laws-registry.json`, 2026-09-22)

**What this is.** One home for every law the product claims to keep. The JSON is the source of truth; this page is
rendered from it; `scripts/smoke-laws.ts` keeps registry and suites in sync in both directions. A law is only alive
while a gate of the right kind enforces it — the Sep 22 audit found ~14 declared laws broken on live data while
their suites were green, because a regex proves wording, not behaviour. Status here reflects that audit, not the
suite colour.

**Gate kinds.** `source` asserts source text · `pure` calls a pure function · `outcome` censuses real/probe data with a
threshold · `walk` is a scripted browser journey. **Cost.** `zero-ai` · `cached` · `live-ai`. **Status.** `holding`
(committed, deployed, earned) · **`holding-uncommitted`** (a Sep 22 finding was fixed in code by a landed wave, but
the fix sits uncommitted/undeployed/unwalked — `Fixed by Wn.n` names the wave) · `BROKEN-LIVE` (a Sep 22 finding
still stands, sometimes because the code fix landed but an owner-gated migration or `--apply` sweep has not run yet
— those carry a `pending_migration`/`pending_apply` note) · `gateless` (no live gate) · `obsolete`. A gate marked
`planned Wn.n` does not count as enforcement. **`holding-uncommitted` is not `holding`**: nothing here is real until
committed, deployed, and (for tier 1) browser-walked.

## THE ADMISSION RULE (how a law enters this registry)

A law is not a law until it has a registry entry, and an entry is refused unless it carries all five:

1. **A statement** in one sentence that a gate can falsify.
2. **Its homes** — the files where the law lives (a law with no home is a wish).
3. **Its collisions** — the registered laws that share a seam, each with a precedence, or the words
   `collides_with: []` written on purpose. An unnamed collision found later is a registry bug charged to
   the entry.
4. **A gate of the right kind** in the same commit: tier 1 needs an outcome census on real or probe data
   with a threshold (and a browser walk per release); tier 2 needs at least a pure-function test naming
   the function; tier 3 needs nothing and claims nothing. A gate may be `planned` only with a wave, and a
   planned gate is not enforcement — the status stays `gateless` or `broken-live` until it runs.
5. **A cost class** per gate (`zero-ai` · `cached` · `live-ai`) so the zero-AI tier runs on every commit
   and the live tier once per wave.

Naming rules: one canonical name, aliases folded in (ONE DOOR / ONE DEED ONE DOOR / ONE RESUME DOOR are one
entry; DISTINCTIVE-TOKEN / SCOPING GUARD / NAMED-SUBJECT VETO / FILING-FOCUS are one primitive,
`namesOverlap`). No two entries share a name or alias — `scripts/smoke-laws.ts` refuses the registry
otherwise. A law that names one account's data is a repair script, not a law (THE AGNOSTIC CLAUSE).

Retiring a law: set `status: obsolete`, move it to tier 3, drop its homes and gates. Its aliases stay so a
stale doc reference still resolves here.

## HOW TO USE THIS (for every agent, every wave)

- **Before touching a seam, read tier 1 whole** (fourteen rows) **and the tier-2 section for the domain you
  are in.** The statement tells you what must stay true; the homes tell you where; the gate tells you what
  will catch you.
- **Status is the audit, not the suite colour.** `BROKEN-LIVE` means a Sep 22 finding names it even if its
  suite is green — read `broken_by` before you assume the law holds. A repair "in flight, uncommitted"
  is not a repair until its gate has re-earned green and the orchestrator has walked it.
- **Never add a law without a registry entry**, and never add an entry without its collisions and a gate
  (the admission rule). Put the entry in `docs/laws-registry.json`; regenerate this page's tables from
  it; run `npx tsx scripts/smoke-laws.ts` — it fails on a missing suite, a duplicate name, a home that
  does not exist, a version key that is not a constant, or an invariant with no outcome/walk gate and no
  plan.
- **When a suite is born, register it.** The meta-gate warns on every `scripts/smoke-*.ts` that serves no
  law; the warning list is the retirement census for suites.
- **When you find a live breach**, set the law `broken-live` with the finding in `broken_by` in the same
  change as the fix, and add the outcome gate that would have caught it. Fix the class, never the
  screenshot; one arc over N patches.
- **Prose docs point here.** CLAUDE.md, the plan docs and the roadmap name laws; this registry defines
  them. If they disagree, the registry is right and the doc is stale.
